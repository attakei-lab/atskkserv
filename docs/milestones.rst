==================
開発マイルストーン
==================

ドキュメント上で管理する範囲での要件は 「 `yaskkserv2`_ を100%置き換えても不都合がない」ことをゴールとする。 [#]_

.. _yaskkserv2: https://github.com/wachikun/yaskkserv2
.. [#] 2026年09月14日時点に各端末で横断運用しているSKK辞書サーバー

v0.0.X
======

「サーバーの体裁は整っている」フェーズ。

* 全てのコマンドの網羅自体はしている。
* REQUESTコマンドに対しては「無条件でcode=4を返す」を初期実装として、
  テスト用にごく一部の見出しのみに対応した「辞書相当の挙動」を検討する。

.. warning::

   前述の要件を見ると判るように、
   このフェーズはSKK辞書サーバーとして「最低限の挙動」は担保するが、
   「最低限の基本動作」を保証しない。

v0.1.X
======

「サーバーとしてフロントには立てる」フェーズ。

* 結果として「SKK辞書サーバーとして機能する」ように振る舞う実装が整った状態。
* コア機能の要件は満たすが、コア外の機能や非機能要件については未保証。

.. note::

   初期実装では、「他のSKK辞書サーバーに対する透過的Proxyとして稼動する」ことを想定。

v0.X.Y
======

「単独稼動が出来る」フェーズ。

SKK辞書サーバーとして単独完結しており、なおかつ利便性が高く「普段使いしそう」な機能の実装を進めていく段階となる。

.. note::

   別の指針として、「既存のdotfilesリポジトリからこれ以外のSKK辞書サーバーを除外する」ことが可能になった段階とする。

v1.0.0
======

「プロダクトとみなしても良いと考える」フェーズ。

次の要件を満している状況になったら移行する。

* "v0.X.Y" 期に出てきた要望のうち「普段使いしそう」といえる領域についての実装がほぼ完了している。 [#]_ [#]_
* ログ出力のような「トラブル時の状況把握」 に必要な実装が一通り完了している。
* 自分以外の環境向けの平易なインストールガイドを提供する。
* (実現するなら)自分以外の利用者を検知する。

.. [#] 実装難易度に応じて、「便利そう」レベルの機能が先行で実装されるケースはある。
.. [#] 実装難易度に応じて、「普段使いしそう」でも他の進捗判定によってはスキップするケースがある。

v1.X.Y
======

v1.0.0移行に検出したバグのフィックスや、APIの互換性を損ねないアップデート。

.. note::

   「SKK辞書サーバー」の想定されうる要件を考慮すると、
   このマイルストーンが終端となる可能性が高い。

vX.Y.Z
======

APIの互換性を失ったアップデートをする場合のフェーズ。

ここでの"APIの互換性"は下記を指す。

* COMPLETIONコマンド ( :doc:`skk/protocol` 未掲載)の意味情報に大きな変化が発生した場合。
* 機能整備に伴い、CLIオプション引数の内容から一部が削除される場合。
* 設定ファイルのフォーマットから定義している項目が削除される場合。

.. note::

   「定義は生きているが完全無視をする」ケースについては要検討とする。

また、どの場合においても「互換性が失われることへのユーザー側対応」をマイグレーションガイドとして執筆できるまでは、vX.0.0のリリースは行わない。
